# Firefin Audit (2026-10-26)

Stand: `main` @ `0e1d6e1`, Version `2.6.0` (versionCode 3001006).
Zielprofil: Fire TV Stick 2. Gen (AFTT), Fire OS 5, API 22, ARMv7, ~1 GB RAM.

Alle Befunde basieren auf Code-Lesen des nativen Moduls `app/` und auf der
lokalen Baseline. Es stand **kein AFTT-Gerät und kein API-22-Emulator** zur
Verfügung; Laufzeitverhalten auf dem Zielgerät ist daher überall als
"unverifiziert" zu lesen, auch wenn die Code-Logik eindeutig ist.

## 1. Orientierung

### 1.1 Architektur (nativ, `app/`)

| Schicht | Dateien | Rolle |
|---|---|---|
| Einstieg | `FirefinApplication`, `ServiceLocator` | Conscrypt-Provider, Trust-Store (Plattform + ISRG Root X1), `JellyfinClient`, zwei `ImageLoader` (privat/TMDB), `PreferenceStore` |
| Transport | `ServerTransport` | Zwei OkHttp-Clients (REST 25 s Call-Timeout; Media ohne Call-Timeout, 30 s Read-Timeout), Origin-Bindung, kein Redirect-Follow (REST), max. 3 same-origin GET-Redirects (Media), Token nur im Header |
| API | `JellyfinClient`, `SeerrClient`, `Models`, `SeerrModels` | org.json-Parsing, `withContext(IO)`, PlaybackInfo-Verhandlung mit `DeviceProfile` |
| Session | `SessionStore`, `*` | SharedPreferences (`firefin_session`, `firefin_preferences` account-gehasht) |
| Bilder | `ImageLoader`, `ArtworkPolicy`, `TmdbArtwork` | 2 globale Decode-Slots, LRU-RAM (16 MB bzw. maxMemory/8), Disk-LRU (48 MB / 16 MB), RGB_565, Bucket-Ladder 160…960 |
| Playback | `PlaybackEngine`, `DeviceProfile`, `PlaybackTimeline`, `StreamSelection`, `SessionReporter`, `PlaybackSessionTracker` | Media3 1.8.1 ExoPlayer auf `PlayerView` (SurfaceView), HLS-Transcode, Session-Reporting mit Terminal-Stop |
| UI | `*Activity`, `Adapters` | 9 Activities, Views/XML, verschachtelte RecyclerViews (Home), Grid (Library/Seerr) |

Navigation: `HomeActivity` (Launcher) → `DetailActivity` → `PlayerActivity`;
Toolbar-Buttons → `SearchActivity`, `LibraryActivity`, `SeerrActivity`,
`SettingsActivity` (→ `RemoteActivity`). `LoginActivity.startFresh` räumt den
Task (`CLEAR_TASK`). Alle Screens: Coroutine-Scope pro Activity, Abbruch in
`onDestroy`. Fokus: XML `nextFocus*` nur in Toolbar und Login; sonst
Framework-`FocusFinder`.

### 1.2 Flutter-Altlasten: Befund (nur Bericht, nichts gelöscht)

`settings.gradle.kts` bindet ausschließlich `:app` ein. Die Verzeichnisse
`lib/`, `android/` (Flutter-Host-Projekt mit eigenem Gradle), `ios/`,
`linux/`, `macos/`, `windows/`, `packages/`, `test/*.dart`, `pubspec.yaml`,
`pubspec.lock`, `.metadata`, `analysis_options.yaml` gehören zur Legacy-
Flutter-App `org.moonfin.firetv32`. Sie werden vom nativen Build **nicht**
berührt. Einzige Referenz: `.github/workflows/build.yml` (Legacy-Validierung,
pfadgefiltert, nie veröffentlicht). `.gitattributes` markiert sie als
`linguist-vendored`. `THIRD_PARTY_NOTICES.md` begründet den Verbleib (Parität).
Empfehlung: unverändert lassen, bis der Besitzer die Parität für erledigt
erklärt; ein Löschen ist ein separater, expliziter Schritt.
